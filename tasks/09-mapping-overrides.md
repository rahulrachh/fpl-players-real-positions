## Notes
- **Code:** `backend/app/mapping/overrides.py` (`load_overrides()`, `OverrideFileError`), applied first in `run_player_mapping()` (`players.py`), so both `python -m app.mapping run` and every sync use it. The file is the only source of override rows: rows are rebuilt each run like the auto rows, so deleting a line hands the player back to auto-matching; unchanged rows keep `matched_at`.
- **Format:** `fpl_id,sofascore_id,comment`; empty `sofascore_id` = force no match (row deleted, player kept out of auto-matching, listed as unmatched with reason `override: forced no match`). Override rows get `match_method = override`, `is_override = true`, confidence 1.0, and their Sofascore ID is taken out of the auto pool (an override can take a Sofascore player from an auto-matched FPL player). Documented at the top of `docs/mapping-coverage.md` (generated by `report.py`) and in `docs/release.md`.
- **Validation:** bad header, non-integer IDs, extra columns, or an FPL / Sofascore ID listed twice raise before anything is written. A row whose FPL player is unknown, or whose Sofascore player is not stored yet, is skipped and reported (report, mapping CLI, sync warning); in the second case the player stays unmatched instead of being auto-matched against the file.
